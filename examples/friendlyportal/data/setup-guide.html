Set up your own portal

Make your own FriendlyPortal with a real domain and a trusted HTTPS certificate — then run it on your laptop or flash it to a board.

0 Install Roost

go install github.com/stevenssparks/roost@latest
# or clone and build:
git clone https://github.com/StevenSSparks/roost
cd roost && go build -o roost .

Make your own image by copying this one:

roost init my-portal          # scaffold a fresh image, or
cp -R examples/friendlyportal my-portal
roost run my-portal           # boots at http://localhost:8080

1 Get a domain

You need a domain you control (e.g. myportal.net). Register one at any registrar — Cloudflare Registrar, Namecheap, Porkbun, etc. A cheap .net or .xyz is fine.

Put the domain's DNS on Cloudflare (the free plan works). You don't need to point it at any server — you just need Cloudflare to answer DNS challenges for the certificate.

2 Get a free, trusted certificate

We use acme.sh with a DNS-01 challenge — no open ports, no public server needed. Create a Cloudflare API token scoped to Edit DNS for your zone, then:

curl https://get.acme.sh | sh          # install acme.sh
export CF_Token="your-cloudflare-api-token"
acme.sh --issue --dns dns_cf -d myportal.net -d '*.myportal.net' --keylength ec-256
Use a publicly-trusted Let's Encrypt cert (what acme.sh issues here) — not a Cloudflare “Origin” cert, which phone browsers won't trust when they connect straight to your box.

3 Install the cert into your image

Set your domain in my-portal/roost.json ("domain": "myportal.net"), then let Roost pull the cert in:

roost cert refresh my-portal       # copies fullchain.pem + privkey.pem into the image
roost cert status  my-portal       # confirm CN + days-to-expiry

Certs last ~90 days; acme.sh auto-renews on a schedule, and the reinstall hook drops fresh files back into your image automatically.

4 Run it

sudo roost run my-portal --setup-hosts    # maps your domain to the box, ports 80/443/53

Open https://myportal.net — clean padlock, your portal. The live console is at http://localhost:9090, and you can ssh into the shell on port 2222.

Only the first run needs sudo (to edit /etc/hosts and bind ports 80/443/53). Prefer no sudo? Use high ports in roost.json (e.g. :8443) and browse https://myportal.net:8443.

5 Flash it onto a real board

The same image folder can run on a Seeed XIAO ESP32-S3 (or similar). Roost builds a LittleFS image from your data/ and writes it over USB:

roost flash-board my-portal                 # prints the plan (safe, no writing)
roost flash-board my-portal --confirm       # actually flash (needs esptool + mklittlefs)
The flash offset/size must match your board's partition scheme (Arduino IDE → Tools → Partition Scheme). Roost prints the exact commands first so you can verify before writing.

That's it 🎉

You now have a pocket-sized Wi-Fi portal with a real certificate, serving whatever you put in data/ — games, docs, an event guide, a neighborhood board. Share the folder and anyone can run your portal.
