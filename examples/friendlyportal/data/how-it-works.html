How it all works

FriendlyPortal is powered by Roost, which runs five tiny services over one shared state. Here's the whole picture.

The captive-portal flow

This is the sequence that happened the moment you joined the Wi-Fi:

1

You join the Wi-Fi

Your phone or laptop connects to an open network broadcast by the box.

2

Your device checks for internet

Every OS quietly requests a known URL (Apple hits captive.apple.com, Android hits /generate_204) to see if it has real internet.

3

The box's DNS answers everything

The box runs its own DNS that resolves every name to itself. So that check lands on the box instead of the real internet.

4

The box redirects to the portal

Instead of the expected reply, the box returns a 302 redirect — and your device pops up this page automatically.

5

You browse the domain

Because DNS points the domain at the box, opening friendlyportal.local serves this whole site — over HTTPS, with a real certificate.

The five services

ServiceWhat it does
🌐 DNSAnswers every lookup with the box's address — the “funnel” that makes the portal and the domain work offline.
📶 HTTPDetects captive-portal probes and redirects them; serves the site on port 80.
🔒 HTTPSServes the same site with TLS. Uses a real cert for the domain if present, or a self-signed one so it always runs.
🖥️ SSHA tiny admin shell — status, top, tail, ls, stats. Watch the box live.
📊 DashboardA live console showing every web hit and DNS lookup as it happens.

All five read and write one shared state (a request log, stats, a virtual filesystem, and a DNS log). That's why a web hit instantly shows up in the SSH tail and on the dashboard at the same time.

An “OS” is just a folder

What we call an image is a plain directory:

friendlyportal/
  roost.json     ← config: name, domain, ports, which services run
  data/            ← the website served (this page lives here!)
  certs/           ← optional: your real TLS certificate

Roost “flashes” that folder and boots it. Copy it, edit data/, and you have your own portal. The same folder is what you'd load onto a real ESP32 board.

Try the shell right now. From a terminal on this network: 
ssh friendly@friendlyportal.local
# password: friendly
friendlyportal# help      # list commands
friendlyportal# top       # live dashboard
friendlyportal# tail      # watch web hits stream in

From emulator to real hardware

Roost runs this all on a laptop for testing, but the same image can be flashed to a Seeed XIAO ESP32-S3 (or similar) so it runs as a real pocket-sized Wi-Fi box. See the setup guide for the domain, certificate, and flashing steps.
